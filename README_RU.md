# upwork-scout — локальный отбор вакансий Upwork

upwork-scout — локальный скрипт для одного пользователя Windows. Один ручной запуск (`run.bat`)
открывает установленный Google Chrome с отдельным профилем (`browser-profile/`); при первом
запуске вы входите в Upwork вручную, дальше сессия сохраняется. Скрипт сам находит на странице
`https://www.upwork.com/nx/find-work/` **все** ваши сохранённые поиски — по ссылкам вида
`/nx/find-work/{id}`, без единого захардкоженного ID или названия — и открывает их один за
другим в одной вкладке. Для каждого поиска он собирает карточки вакансий (при необходимости
нажимая «Load More Jobs» и открывая страницы вакансий), объединяет дубликаты по ID вакансии в
SQLite, применяет жёсткие правила и прозрачную оценку 0–100, при наличии ключа опционально
спрашивает мнение Jev через OpenRouter и записывает отчёт
`outputs/upwork-report-YYYY-MM-DD-HH-mm.html`. Скрипт работает только на чтение: он не
откликается на вакансии, не пишет сообщения, ничего не сохраняет и не ставит реакций на Upwork.

## Стек

- Python 3.11+ (проверено на 3.14)
- Playwright, `channel="chrome"` — управляет установленным Google Chrome, а не отдельным Chromium
- BeautifulSoup — разбор HTML
- SQLite — хранение вакансий, поисков и оценок
- Jinja2 — HTML-отчёт
- PyYAML — `config.yaml`
- pydantic — валидация настроек
- httpx — запросы к Jev через OpenRouter
- python-dotenv — чтение `.env`
- pytest — тесты

## Структура проекта

```
upwork_scout/
  app.py            — точка входа CLI: разбор аргументов, логирование, коды выхода
  browser.py        — драйвер Playwright: установленный Chrome, одна вкладка, только чтение
  scraper.py         — один проход по всем сохранённым поискам (вход, поиск, сбор, детали)
  discovery.py        — динамический поиск сохранённых поисков на странице Find Work
  parsing.py           — разбор карточек вакансий и страниц вакансий в объекты Job
  guards.py            — распознавание CAPTCHA/проверки безопасности/страницы входа
  ids.py                — нормализация ID вакансий и ID сохранённых поисков
  htmltext.py           — извлечение читаемого текста из HTML (BeautifulSoup)
  textmatch.py           — сопоставление фраз: без учёта регистра, по границам слов, с `*`
  models.py               — датаклассы Job и SavedSearch, слияние дублей, хеш содержимого
  scoring.py                — жёсткие правила исключения + объяснимая оценка 0–100
  ai.py                       — необязательный этап AI-оценки через Jev (OpenRouter)
  storage.py                   — хранилище SQLite (запуски, поиски, вакансии, оценки)
  pipeline.py                    — оценка вакансий запуска и сборка контекста отчёта
  report.py                       — рендеринг HTML-отчёта (Jinja2)
  fmt.py                            — общее форматирование (деньги, возраст, бюджет…)
  config.py                          — загрузка и валидация config.yaml и .env
  templates/report.html.j2            — шаблон HTML-отчёта
config.yaml            — некритичные настройки (см. раздел «Настройка config.yaml»)
.env / .env.example    — секреты (ключ OpenRouter) и их шаблон
run.bat                — запуск скрипта в .venv
tests/ (+ fixtures)    — тесты на локальных HTML-фикстурах, без сети и браузера
data/                  — SQLite-база (data/upwork.sqlite3), создаётся автоматически
outputs/                — HTML-отчёты запусков
logs/                    — файл лога (logs/upwork-scout.log)
browser-profile/          — отдельный постоянный профиль Chrome для скрипта
debug/                      — очищенный HTML пустых страниц поиска (только если collection.debug_dump_html: true)
```

## Установка

```
python -m venv .venv
source .venv/Scripts/activate        # Git Bash
.venv\Scripts\activate               # cmd / PowerShell
pip install -r requirements.txt
```

Google Chrome должен быть установлен в системе. Команда `playwright install` не нужна — скрипт
использует уже установленный Chrome через `channel="chrome"`, а не отдельно скачанный Chromium.

## Первый запуск и вход

Запустите:

```
run.bat
```

(или `.venv\Scripts\python -m upwork_scout`). Откроется окно Chrome с папкой профиля
`browser-profile/` — отдельной от вашего повседневного профиля Chrome; скрипт откажется
работать, если `browser.profile_dir` указывает на `%LOCALAPPDATA%\Google\Chrome\User Data`.
Войдите в Upwork вручную в открывшемся окне; скрипт ждёт до `browser.login_timeout_minutes`
(по умолчанию 10 минут) и продолжает сам, как только видит, что вы вошли. Пароль и cookies
никогда не попадают в код, логи или отчёт — сессия хранится только в `browser-profile/`.

Чтобы только войти и ничего не собирать:

```
run.bat --login-only
```

Во время фазы входа скрипт только наблюдает и ничего не нажимает: если Upwork показывает
проверку, пройдите её сами вручную. После того как проход начался (вход подтверждён), любая
CAPTCHA/проверка безопасности или страница входа останавливает весь проход целиком — но уже
собранные к этому моменту данные сохраняются, и отчёт всё равно создаётся.

## Обычный запуск

```
run.bat
```

| Флаг | Что делает |
|---|---|
| `--show-all` | показать в отчёте все найденные вакансии, а не только новые |
| `--no-ai` | не использовать AI-оценку (Jev) в этом запуске |
| `--no-details` | не открывать страницы вакансий (быстрее) |
| `--load-more N` | сколько раз нажимать «Load More Jobs» в каждом поиске (0–50) |
| `--rescore` | без браузера: пересчитать оценки последнего запуска по текущему `config.yaml` и создать новый отчёт |
| `--login-only` | только открыть Upwork в профиле скрипта и дождаться входа (без сбора) |
| `--config PATH` | путь к `config.yaml` (по умолчанию — в папке проекта) |
| `--version` | показать версию и выйти |

Коды выхода: `0` — успех, `1` — сбой, `2` — ошибка настроек, `3` — проход остановлен
(security check, потеря сессии, закрытие окна и т. п.; отчёт по уже собранным данным всё
равно создаётся).

## Настройка config.yaml

Все некритичные настройки — в `config.yaml`, пути относительно папки проекта.

- **browser** — профиль и тайминги Chrome: `profile_dir` (отдельный профиль), `channel`
  (`chrome`), `login_timeout_minutes` (10 — сколько ждать ручного входа),
  `navigation_timeout_seconds` (45), `discovery_wait_seconds` (25 — ожидание, пока список
  вкладок сохранённых поисков перестанет меняться), `cards_wait_seconds` (20 — ожидание
  карточек на странице поиска), `delay_between_pages_seconds` (`[3, 6]` — случайная пауза
  между переходами, спокойный темп в одной вкладке).
- **upwork** — `find_work_url`, страница со списком сохранённых поисков.
- **collection** — сбор карточек: `load_more_clicks` (сколько раз нажать «Load More Jobs»),
  `load_more_wait_seconds`; `details.mode`: `off` — не открывать страницы вакансий (быстрее
  всего), `missing` — открывать, только если в карточке не хватает ключевых полей, `always` —
  открывать страницу каждой подходящей вакансии (полное описание); `details.only_new` —
  открывать страницы только новых вакансий; `details.max_per_run` (40) — не больше N страниц
  вакансий за запуск; `debug_dump_html` — сохранять HTML страниц поиска без единой карточки в
  `debug/` (для диагностики изменений интерфейса Upwork). Файл очищается: остаётся только
  `<main>` без скриптов, форм, скрытых полей, шапки/меню аккаунта и лишних атрибутов; ссылки
  сохраняются только на вакансии и сохранённые поиски. Перед тем как кому-то отправлять такой
  файл, всё равно просмотрите его — в тексте страницы может быть ваше имя.
- **storage** — `db_path` (`data/upwork.sqlite3`).
- **report** — `show`: `new` — только вакансии, которых не было до запуска, `all` — все
  найденные; `show_below_threshold` и `show_excluded` — показывать ли в отчёте свёрнутые блоки
  «ниже порога» и «отсеяны жёсткими правилами».
- **logging** — `file`, `level`.
- **filters** (жёсткие правила, применяются до оценки) — `min_fixed_budget` (100),
  `min_hourly_rate` (15); `exclude_in` (`[title, skills]`) — где совпадение стоп-фразы означает
  полное исключение вакансии, в остальных местах (обычно в описании) совпадение даёт лишь штраф
  категории; `soften_if_stack_in_title_or_skills` — если в заголовке или навыках есть
  приоритетный стек (`scoring.stack`), стоп-фраза не исключает вакансию, а только штрафует;
  `description_penalty_share` (0.5) — доля штрафа категории, если стоп-фраза встретилась только
  в описании; `stop_categories` — категории (`marketing`, `crypto_trading`, `data_entry`,
  `design`), у каждой `label`, `penalty` и список `phrases`.
- **scoring** (оценка 0–100) — `min_score` (40, итоговая оценка ≥ него → «прошла фильтр»),
  `recommend_apply_from` (70, ≥ — «откликнуться»), `recommend_review_from` (45, ≥ — «проверить
  вручную», ниже — «пропустить»), `unknown_share` (0.5 — если поле не указано/не загрузилось,
  компонент получает эту долю своего максимума: отсутствие данных ≠ плохое значение).
  Компоненты и их максимум: `stack` до 40 (совпадение с приоритетным стеком: заголовок ×1.5,
  навыки ×1.25, описание ×1.0), `freshness` до 10 (свежесть публикации), `competition` до 10
  (количество откликов, чем меньше — тем лучше), `client` до 20 (оплата подтверждена + расходы
  клиента + рейтинг), `budget` до 10 (бюджет/ставка), `clarity` до 10 (конкретный ограниченный
  объём работы: длина описания, фразы про результат, списки пунктов). `penalties` — штрафы за
  неподтверждённую оплату, низкий рейтинг клиента, слишком короткое описание, расплывчатые
  формулировки, «огромный объём при символическом бюджете» и совпадения со стоп-категориями.
- **ai** — параметры этапа Jev (см. раздел ниже).

Фразы (в `filters.stop_categories.*.phrases`, `scoring.stack.*.phrases`,
`scoring.clarity.scope_phrases`, `scoring.penalties.vague_phrases` и др.) сопоставляются без
учёта регистра, по границам слов; символ `*` в конце фразы означает совпадение по началу слова
(`"cold email*"` совпадёт с «cold emails»).

Совет: после изменения весов запустите `run.bat --rescore`, чтобы увидеть эффект без открытия
Upwork.

## Подключение сторонних сервисов и API

AI-этап использует **Jev by TypeSafe** через **OpenRouter**.

1. Создайте аккаунт на https://openrouter.ai и пополните баланс (кредиты).
2. Получите ключ на https://openrouter.ai/settings/keys .
3. Впишите его в `.env`:

   ```
   OPENROUTER_API_KEY=ваш_ключ
   ```

   Если оставить значение пустым, скрипт возьмёт ключ из переменной окружения Windows
   `OPENROUTER_API_KEY`, если она задана; иначе AI-этап будет пропущен.

Переменные `.env` (см. `.env.example`):

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `OPENROUTER_API_KEY` | ключ OpenRouter | — (пусто → берётся из окружения) |
| `JEV_MODEL` | модель Jev на OpenRouter | `~typesafe/jev-latest` |
| `JEV_API_URL` | endpoint System One API | `https://openrouter.ai/api/v1/systemone` |

Документация: https://openrouter.ai/docs/guides/community/jev ,
https://openrouter.ai/docs/guides/community/typesafe-sdk , https://openrouter.ai/typesafe .

**Что отправляется:** только публичные поля вакансии — заголовок, описание (обрезанное до
`ai.description_max_chars`), навыки, бюджет, уровень, длительность, количество откликов, статус
оплаты клиента / его рейтинг / расходы / страна. Дата публикации не отправляется: свежесть
оценивают детерминированные правила. **Что никогда не
отправляется:** cookies, содержимое профиля браузера, данные аккаунта Upwork.

Jev возвращает типизированные решения, а не свободный текст: оценку релевантности по шкале
0–4 (переводится в 0–100), выбор `apply`/`review`/`skip` и вероятность (noul) для каждого
настроенного вопроса о риске. Текст объяснения в отчёте составляется из этих типизированных
ответов. Ориентировочная стоимость одного запроса — около $0.00002.

Без ключа проект работает только на детерминированных правилах, а в отчёте указывается, что
AI-этап не выполнялся. Таймаут, HTTP 429 и 5xx повторяются
(`ai.max_retries`); некорректный JSON или несоответствие схеме не повторяются. Если оценка не
получена, у вакансии в отчёте пишется «AI-оценка не выполнена», а оценка правил сохраняется.
Ошибки 401/402 или исчерпанный лимит 429 останавливают AI-этап до конца запуска, как и
`ai.max_consecutive_failures` ошибок подряд. Результаты кешируются по отпечатку всех входных
данных: отправленные поля вакансии, модель, вопросы, порог риска и версия интерпретации. Если
изменить `ai.freelancer_focus`, вопросы, порог или модель, Jev будет спрошен заново. AI никогда не отменяет
жёсткие исключения, если явно не включено `ai.override_exclusions: true`.

`.env.example` должен оставаться структурно идентичным `.env` (те же переменные, тот же
порядок, отличаются только значения). Проверка расхождений (вывод должен быть пустым):

```bash
diff <(sed -E 's/=.*/=<V>/' .env) <(sed -E 's/=.*/=<V>/' .env.example)
```

## Отчёт

Заголовок отчёта показывает: сколько поисков обработано (из скольких найдено), сколько
уникальных вакансий, сколько новых, сколько прошло фильтр, сколько поисков завершилось
ошибкой, и сводку по AI-этапу (модель, число успешных/неудачных запросов, стоимость).

Каждая карточка вакансии показывает: итоговую оценку `/100` с раскладкой на оценку по правилам
и вклад Jev, шкалу из 6 сегментов (стек / свежесть / отклики / клиент / бюджет / ясность),
бюджет, данные клиента, количество откликов, дату публикации, список причин («почему
подходит»), список рисков с указанием вычета баллов, рекомендацию (откликнуться / проверить
вручную / пропустить), список поисков, в которых встретилась вакансия, навыки и описание.

Свёрнутые блоки «Ниже порога» и «Отсеяны жёсткими правилами» показывают вакансии, которые не
прошли фильтр по баллам или были исключены правилами (управляются `report.show_below_threshold`
и `report.show_excluded`).

`«не указано»` означает, что поле не было показано Upwork на карточке/странице — это не «плохое»
значение, а отсутствие данных. Весь текст, пришедший с Upwork (заголовки, описания, названия
поисков), экранируется как HTML (автоэкранирование Jinja2), так что ничего со страницы Upwork
не может исполниться как код в отчёте.

## Хранение данных

Данные хранятся в SQLite (`data/upwork.sqlite3`) в таблицах:

- `runs` — каждый запуск скрипта (статус, время, путь к отчёту);
- `searches` — сохранённые поиски (ID, название, URL);
- `search_runs` — результат каждого поиска в каждом запуске (ok/error/aborted/skipped, число
  карточек);
- `jobs` — одна строка на вакансию (по её ID), последняя известная версия полей;
- `job_searches` — в каких поисках встречалась вакансия;
- `sightings` — в каком запуске вакансия была увидена в каком поиске;
- `evaluations` — оценка вакансии в конкретном запуске (правила + AI).

Вакансия считается **новой** в запуске, если её ID не было в базе до начала этого запуска
(`first_seen_run_id` запуска совпадает с текущим). Данные фиксируются (commit) после обработки
каждого поиска, поэтому прерванный проход не теряет уже собранное.

При обновлении проекта база переводится на новую схему автоматически (`PRAGMA user_version`,
недостающие столбцы добавляются через `ALTER TABLE`), накопленные данные сохраняются.
У каждой вакансии хранится число попыток открыть её страницу (`details_attempts`) и
последняя ошибка (`details_last_error`), а также отметка об отложенном открытии
(`details_pending`).

## Тесты

```
.venv\Scripts\python -m pytest -q
```

Тесты используют локальные HTML-фикстуры из `tests/fixtures/` и не обращаются ни к сети, ни к

## Известные ограничения

- Upwork регулярно меняет разметку страниц. Парсинг многослойный: сначала атрибуты
  `data-test`/аналоги, затем текстовые паттерны — но после редизайна часть полей может выйти
  как «не указано», а на странице поиска может не найтись ни одной карточки. В этом случае
  включите `collection.debug_dump_html: true` в `config.yaml` и посмотрите сохранённые файлы в
  `debug/`.
- Сохранённые поиски должны быть видны как ссылки `/nx/find-work/{id}` на странице Find Work.
  Если Upwork прячет часть поисков за дополнительным меню, скрипт их не найдёт — жёстко
  прописанного списка поисков «на замену» нет и не будет.
- Относительные даты («2 hours ago») переводятся в приблизительную метку времени, а не в точное
  время публикации.
- Описание в карточке может быть обрезано Upwork; чтобы получать полный текст, используйте
  `collection.details.mode: always` (открывает страницу каждой подходящей вакансии).
- Рейтинг клиента `0` (нет отзывов) в отчёте сохраняется и показывается как «не указано».
- Скрипт не обходит CAPTCHA/проверки безопасности — при их появлении проход останавливается.
  Проверка при разработке: без входа Upwork сразу показывает браузеру под управлением
  Playwright проверку Cloudflare (заголовок локализуется, например «Один момент…») — скрипт её
  распознаёт. Если после вашего входа Upwork будет показывать проверку на каждой странице,
  проход будет останавливаться на первом поиске: это ожидаемое поведение, а не ошибка.
- Страница вакансии (углублённый сбор) сохраняется, только если это действительно страница
  запрошенной вакансии: она загрузилась, ID в адресе совпадает с ID вакансии (совпадение
  заголовка доказательством не считается), вакансия не удалена и есть минимальные данные.
  Иначе ничего не записывается, а страница открывается повторно в следующих запусках — до
  `collection.details.max_attempts` раз (по умолчанию 3), даже при `only_new: true`.
  Вакансии, не поместившиеся в `collection.details.max_per_run`, помечаются как отложенные и
  открываются в следующих запусках первыми — если снова встретятся в ленте поисков. Страницы
  вакансий, которые из ленты пропали, не открываются: они уже не попадут ни в один отчёт, а
  лишние запросы к Upwork не нужны.
- Список сохранённых поисков считается загруженным, когда набор ID не меняется 3 с (и прошло
  не меньше 4 с после появления первого). Если к концу `browser.discovery_wait_seconds` список
  ещё менялся, в отчёте появится предупреждение.
- Живой интерфейс Upwork не был проверен разработчиком вживую. На первом запуске сверьте
  количество поисков, число карточек и содержимое полей в отчёте с тем, что видно на сайте.
- Jev не возвращает произвольный текст, поэтому объяснения в отчёте составлены из вероятностей
  и типизированных ответов, а не являются дословным комментарием модели.

## Обновление проекта

Сервер не используется — всё работает локально на вашей машине.

1. Скопируйте новые файлы поверх старых (сохранив `.env`, `data/`, `outputs/`, `logs/`,
   `browser-profile/`).
2. Обновите зависимости:

   ```
   source .venv/Scripts/activate        # Git Bash
   .venv\Scripts\activate               # cmd / PowerShell
   pip install -r requirements.txt
   ```
3. Запустите как обычно:

   ```
   run.bat
   ```
